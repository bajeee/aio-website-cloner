# Reconstruct the inspected website

## Decide after inspection

For each substantial subsystem record `reuse`, `recover`, `rebuild` or `hybrid`, supporting evidence and the tradeoff. Respect an explicit project strategy. In auto mode:

- Reuse suitable original assets, CSS and comprehensible independent browser code when permitted and verifiable.
- Prefer actual available source/source-map content to recovered approximations.
- Recover only modules relevant to an unresolved behavior. Inspect outputs and limitations before adopting them.
- Rebuild where source is unavailable, tied to the original server, unsafe to retain or unsuitable for editing. A visually plausible approximation remains a recorded gap until compared.

Keep an existing target stack unless the task requires change. For a new target choose the simplest framework/deployment shape that supports the observed routing and interaction model. Do not force every website into the starter's framework or add a server for a static frontend.

## Implement shared foundations first

Match loaded fonts and their metrics, width constraints, typography, image crop and layers before small spacing adjustments. Preserve responsive rules, real text and section order. Scope styles when multiple independent sources share an application. Resolve collisions deliberately; avoid global substitutions across unrelated components.

Implement shared header/menu/footer and all observed states once. Use these foundations for route/template work. When delegation is available and authorized, assign non-overlapping ownership and provide reference evidence, asset mapping and acceptance criteria; shared-file changes retain one owner.

Use CSS for simple transitions and reveals. Use a compatible motion runtime when choreography, smooth scrolling, scrubbing or pinning requires it. Preserve trigger rules, timing, order, interruption, reverse scroll and reduced-motion behavior. Clean up listeners, tweens, observers and GPU resources on navigation. Verify actual canvas/WebGL rendering and its fallback; a placeholder or disabled effect does not count as parity.

## Routing and runtime independence

Preserve discovered pathnames and functional query/hash states. Handle refresh, client navigation, back/forward, trailing slashes, encoded segments, completion pages and genuine 404s. Do not invent routes to satisfy a count.

Rewrite internal destinations and URL-bearing metadata to the intended local/deployed origin. Handle CSS URLs, srcset, form actions, script navigation and redirects, not only visible anchors. Keep legitimate outbound links unless the request specifies replacements; inventory external navigation separately from remote resource dependencies.

Localize required fonts/media/code. Replace original API endpoints, write actions, analytics and copied tracking/API identities as appropriate to the agreed mode. A real external integration must be explicitly configured and reported; it disqualifies a strict offline claim.

## Backend modes and intentional differences

- **demo (default):** recreate client-side state and validation with local data. Clearly identify simulated outcomes before submission. Do not send to the original backend, imply a confirmed transaction or retain entered personal information without a requirement.
- **none:** omit backend behavior only when requested, and disclose affected controls. Preserve the agreed visible state.
- **real:** establish project-specific behavior, data, endpoints, secrets and deployment requirements. Do not infer these from a captured form or reuse upstream credentials.

Brand/text/contact changes are project input, not universal cleanup. Record the exact affected elements/scenarios and expected replacement. Apply case-aware targeted changes, review broader matches, preserve required license notices and keep raw original references unchanged. Comparison exemptions must be narrow, visible and traceable; they may not hide missing sections.
